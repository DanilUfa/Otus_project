ДЕМОНСТРАЦИЯ ИМПОРТЁРА ЗАЯВОК

Запуск: двойной щелчок по demo-importer.bat в корне проекта.

Перед показом запустите Docker Desktop. Приложение должно работать:
http://localhost:5000
Если оно остановлено: из корня проекта выполните docker compose up -d --no-build.

Скрипт откроет сайт. Войдите сотрудником:
Почта: petr@vac.local
Пароль: User123!

На каждом этапе прочитайте пояснение в консоли и нажмите Enter.
Для наблюдения за заявками оставьте рядом окно сайта и окно демонстрации.

Проверка импорта

1. После valid.csv обновите «Мои заявки». У Петра появятся две заявки.
   Их ID видны в журнале dispatches.
2. Для mixed.csv ожидается Imported=1 Errors=2. Команда errors покажет
   номера строк с неверной датой и пересечением отпусков.
3. При повторе valid.csv обе строки получат Duplicate. Импортёр сверяет
   RequestId со своим журналом перед отправкой в API.
4. Файл с неверным заголовком отклоняется до создания задачи.
5. В конце скрипт сверяет заявки по метке запуска. Всего должно быть три.

ОСОБЕННОСТИ СТЕНДА

Импортёр обращается напрямую к основному API внутри сети Docker.
У него отдельная демонстрационная БД; рабочая БД приложения не заменяется.
Каждый полный показ добавляет три демонстрационные заявки Петра.
Повторный запуск выбирает свободные даты и генерирует новые UUID.
Заявки имеют уникальную причину с префиксом import-demo-.
После показа БД и история остаются для повторного использования.
Пароль демонстрационной БД генерируется автоматически и хранится локально
в зашифрованном Windows виде. Не удаляйте db-password.xml, сохраняя том БД.

CSV, результат result.json и журнал demo.log сохраняются в:
.local-demo\importer\runs\<метка запуска> относительно корня проекта

Проверка готовности без импорта: demo-importer.bat --check
Полный прогон без пауз и открытия браузера: demo-importer.bat --auto
