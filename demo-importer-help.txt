ДЕМОНСТРАЦИЯ ИМПОРТЁРА ЗАЯВОК

Запуск: двойной щелчок по demo-importer.bat в корне проекта.

Перед показом запустите Docker Desktop. Приложение должно работать:
http://localhost:5000
Если оно остановлено: из корня проекта выполните docker compose up -d --no-build.

Скрипт откроет сайт. Войдите сотрудником:
Почта: petr@vac.local
Пароль: User123!

На каждом этапе прочитайте пояснение в консоли и нажмите Enter.
Для наблюдения за заявками оставьте рядом окно сайта и окно демонстрации.

ЧТО РАССКАЗЫВАТЬ

1. Успешный импорт.
«Импортёр получает CSV-файл. У каждой строки есть собственный RequestId,
пользователь, тип отсутствия, даты и причина. Две корректные строки отправляются
в API и создают две заявки. В журнале отправок сохраняются их ID».
После выполнения обновите список заявок на сайте.

2. Частичный успех.
«Ошибки одной строки не мешают обработке остальных. Здесь одна заявка создана,
одна строка отклонена из-за некорректной даты, ещё одна — из-за пересечения дат.
В PostgreSQL сохранены задача, счётчики и ошибки с номерами строк».
Ожидаемый результат: Total=3 Imported=1 Errors=2.

3. Повторная отправка.
«Повторяем тот же файл с прежними UUID. Импортёр находит RequestId в своей БД,
возвращает Duplicate и не отправляет заявки повторно».
Ожидаемый результат: Total=2 Imported=0 Errors=2.
Это защита от повторного импорта по журналу RequestId; API само по этому UUID
дедупликацию не выполняет. Не нужно обещать exactly-once при потере HTTP-ответа.

4. Некорректный файл.
«До регистрации задачи выполняется preflight: проверка структуры CSV.
Файл с неверным заголовком отклоняется, новая задача не создаётся».

5. Сверка результата.
«Итого создано три заявки. Повторный файл и ошибочные строки новых заявок
не добавили. ID в отчёте импортёра можно сопоставить с заявками приложения».

ЧТО ПОКАЗАТЬ В КОДЕ

Program.cs -> ImportRunner: фасад запуска команды.
Csv/CsvSnapshot.cs: асинхронный итератор CSV через await foreach.
RowPipeline.cs: bounded Channel, workers и SemaphoreSlim.
Http/LeaveApi.cs: адаптер между строкой импорта и HTTP API.
Persistence/JobStore.cs: PostgreSQL, журнал RequestId, результаты и транзакции.
Файлы находятся в src\VacationPlanner.Importer относительно корня проекта.

ОСОБЕННОСТИ СТЕНДА

Импортёр обращается напрямую к основному API внутри сети Docker.
У него отдельная демонстрационная БД; рабочая БД приложения не заменяется.
Каждый полный показ добавляет три демонстрационные заявки Петра.
Повторный запуск выбирает свободные даты и генерирует новые UUID.
Заявки имеют уникальную причину с префиксом import-demo-.
После показа БД и история остаются для повторного использования.
Пароль демонстрационной БД генерируется автоматически и хранится локально
в зашифрованном Windows виде. Не удаляйте db-password.xml, сохраняя том БД.

CSV, результат result.json и журнал demo.log сохраняются в:
.local-demo\importer\runs\<метка запуска> относительно корня проекта

Проверка готовности без импорта: demo-importer.bat --check
Полный прогон без пауз и открытия браузера: demo-importer.bat --auto
